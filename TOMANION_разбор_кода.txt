================================================================================
1. entities.py — уход от hasattr
================================================================================

ПРОБЛЕМА

Вспомогательные функции проверяли атрибуты через hasattr вместо явной типизации:

  - spike — только у BurgerSpike
  - x_min / x_max — у BurgerSpike, ExplosiveCola
  - x1 / x2 — у DonutPatrol
  - vx — у горизонтальных врагов, но не у JumpingFries

Это duck typing «наугад»: при добавлении нового врага легко забыть атрибут,
код хрупкий и плохо читается.

РЕШЕНИЕ

Базовый класс Enemy — методы-заглушки (no-op для врагов без нужного поведения):

  sync_attachments()         — синхронизация «прицепленных» частей (шип бургера)
  shift_patrol(dx)           — сдвиг границ патруля при расстановке уровня
  clamp_patrol()             — удержание внутри патруля
  reverse_apart(direction)   — разворот при столкновении с другим врагом
  reflect_from_hazard(...)   — отскок от разлитой колы

Промежуточные классы:

  - HorizontalPatrolEnemy → BurgerSpike, ExplosiveCola (патруль x_min/x_max)
  - RangePatrolEnemy → DonutPatrol (патруль x1/x2)

JumpingFries ничего не переопределяет — прыгает по Y, не ходит по X.

РЕЗУЛЬТАТ

  - Удалены все 11 вызовов hasattr
  - Публичный API (keep_enemy_off_cola, separate_enemies и т.д.) сохранён
  - game.py и levels.py не менялись
  - Поведение игры проверено вручную — без регрессий

================================================================================
2. level_transition.py — «ИИ-почерк» и баг с волной
================================================================================

ПРИЗНАКИ СГЕНЕРИРОВАННОГО КОДА

  1. Избыточная математика — sin для прыжка и хвоста ракеты, math.hypot
     для каждой ячейки сетки
  2. Микро-методы в горячем цикле — _cell_closed + _cell_flip_scale
     вызывались ~1000+ раз за кадр
  3. Docstring и «идеальный» PEP 8 при минимальной документации в проекте
  4. _fire_seed = ticks() % 997 — типичный паттерн псевдослучайности

ГЛАВНЫЙ БАГ

_build_wave(reverse=True) менял только константу кадров (OPEN_FRAMES вместо
CLOSE_FRAMES), но НЕ инвертировал волну:

  - Закрытие: от краёв к центру — OK
  - Открытие: снова от краёв — ОШИБКА (должно быть от центра к краям)

ИСПРАВЛЕНИЯ

  Было                              → Стало
  reverse только менял span         → (max_d - d) / max_d, центр открывается раньше
  _cell_closed + _cell_flip_scale   → одна ветка в _draw_grid
  sin для прыжка                    → парабола 4 * p * (1 - p)
  sin для пламени                   → (frame + row) % 5
  _fire_seed % 997                  → убрано

Проверка: угол закрывается на кадре ~1, центр ~40; при открытии центр ~7, угол ~46.

================================================================================
3. progress.py — I/O-спам на диск
================================================================================

ПРОБЛЕМА

Каждый вызов load_* / save_* / add_coins:

  1. Читал весь progress.json с диска
  2. Менял одно поле
  3. Перезаписывал файл целиком

При массовом убийстве врагов или при отрисовке меню (60 FPS) — фризы.

ДОПОЛНИТЕЛЬНО В menu.py

  _draw() на главном экране  — _refresh_shop_state() каждый кадр
  _draw_shop()                 — _refresh_shop_state() каждый кадр
  _draw_levels()               — load_progress() каждый кадр
  _draw_main()                 — _continue_level() каждый кадр для подсказки

РЕШЕНИЕ В progress.py

  - Кэш в памяти (_data) — одна загрузка при первом обращении
  - flush() — запись на диск только если данные менялись (_dirty)
  - add_coins() — только память (игра копит монеты в self.coins)
  - except OSError: pass → print(..., file=sys.stderr)

РЕШЕНИЕ В menu.py

  - Убран _refresh_shop_state() из _draw и _draw_shop
  - self.continue_level вместо _continue_level() каждый кадр
  - self.max_unlocked обновляется при входе в экран уровней

РЕЗУЛЬТАТ

  10 вызовов add_coins() → 1 чтение с диска вместо 10 пар read/write.
